# v0.4.0 출시 확인표

## GitHub Stable

1. `main`의 CI 결과와 포함 구성요소의 고정 SHA를 확인한다.
2. 의존성·라이선스 검토 기록, 호환성 검증 기록, 저장 상태 호환성과 배포물의
   제3자 자료 포함 여부를 최종 확인한다.
3. `v0.4.0` 릴리즈 초안의 본문을 `docs/releases/v0.4.0.md`와 대조하고 공개한다.
   릴리즈 공개가 `build.yml`의 Stable 빌드를 시작한다.
4. 빌드가 성공하면 APK와 AAB, 데스크톱·웹 배포물, `SHA256SUMS.txt`가
   릴리즈에 첨부되었는지 확인한다.

## Google Play

1. Play Console에 이미 업로드된 최고 `versionCode`를 확인한다. 릴리즈
   워크플로의 run number가 그보다 커야 한다. 수동 업로드로 더 높은 코드를
   사용한 적이 있다면 릴리즈를 공개하기 전에 빌드 설정을 조정한다.
2. 릴리즈 자산 `aram-google-play.aab`의 패키지 ID
   `io.github.mirusu400.aram`, 버전 이름 `0.4.0`, 버전 코드와 업로드 서명을
   확인한다.
3. Play Console의 스토어 등록정보, 스크린샷, 개인정보처리방침, 데이터 보안,
   광고·동의 설정과 앱 액세스 정보를 검토한다.
   Play App Signing 인증서가 `aram.mir.sh/.well-known/assetlinks.json`에
   포함되어 있는지도 확인한다.
4. 한국어 업데이트 문구는 `store/play/whats-new-ko-KR.txt`, 영어 문구는
   `store/play/whats-new-en-US.txt`를 사용한다.
5. 내부 테스트에서 설치·실행·게임 열기·저장 데이터 재실행 복원·백업 내보내기와
   광고 동의 흐름을 확인한 뒤 출시 트랙에 AAB를 제출한다.

Play App Signing 인증서가 GitHub Stable APK의 인증서와 다르면 Android가
기존 앱 위에 Play 버전을 설치하지 않는다. 전환 전 백업을 내보내도록 안내한다.
